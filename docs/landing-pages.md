# Landing pages and application entry points

## What this repository serves

This repository contains the NotesAI-RNA application frontend. Its `index.html` is a minimal Vite shell with the document title, viewport, app icons, manifest link, and `#root` mount point. React renders the user experience into that mount point.

The **Home** component (`src/components/Home.jsx`) is the in-app welcome and feature landing screen. It is not an unauthenticated public product-marketing site. The app does not currently define separate static marketing pages or a route-per-page router.

## Entry and navigation flow

1. The browser loads `index.html` and `src/main.jsx` mounts `App`.
2. `App` initializes authentication, shows a brief opening animation, and starts in the Home view.
3. The main navigation changes the active view in application state. The app shell includes Home, Notes, Tasks, NotesAI, Shares, Notifications, Troubleshooting, and Account.
4. If a URL has a `share` query parameter, `App` opens the matching shared resource view. For example, a deployment may issue a URL shaped like `https://<app-host>/?share=<share-token>`.
5. If a URL has both `uid` and `token` query parameters, the Account panel enters the password-reset confirmation flow. These values are supplied by the backend’s reset email.
6. Help topics are selected with a hash such as `#help/ai` or `#help/navigation`. Closing help removes the hash and restores focus to the previous control.

Because major app views are selected by React state, direct links to ordinary views are not stable route URLs. Keep share and password-reset URL formats aligned with the backend.

## Home screen content

The Home screen introduces the study workspace and offers shortcut actions to Notes, Tasks, and NotesAI. It also shows rotating motivation and study tips, a small feature overview, and an invite notice when the signed-in user has pending share invitations.

For changes to this screen, edit `src/components/Home.jsx` and its related styles in `src/styles.css` / feature styles. Keep primary shortcuts usable by keyboard and on narrow screens, and ensure the wording matches the features available in the app.

## Document metadata and discoverability

The current HTML shell sets the page title to `NotesAI-RNA`, declares English, and includes viewport and app icon/manifest metadata. It does not include a dedicated public marketing page, page-specific metadata, or a server-rendered landing route. The PWA manifest is generated by the Vite PWA configuration in `vite.config.js`.

If a public marketing landing page is added later, decide whether it belongs in this application or on a separate site. A public page should have its own descriptive title and summary, clear sign-in or app-launch actions, responsive layout, and appropriate social preview metadata. Avoid presenting private account content to unauthenticated visitors.

## Deployment behavior

The frontend is a single-page app and the app entry must be served for the root path. Shared links and password-reset links also depend on the host serving the app shell for their query-string URLs. Configure the static host’s fallback behavior accordingly. The PWA uses root scope and root start URL as configured in `vite.config.js`; deployments under a subpath may need matching Vite base, manifest, and asset-path changes.
